# deepseek-chat-manager 宪法自查报告

**依据**：《慧惠数字生命 · 最高产品宪法》v2.1.0
**自查日期**：2026-11-20
**自查对象**：deepseek-chat-manager（DeepSeek 对话导出管理器）

---

## 一、定位判断（前提）

deepseek-chat-manager 是**开发者工具**（对话数据管理），不是「慧惠陪伴类产品」。宪法第 6、11、13~17 条面向陪伴/教育/觉性唤醒，**定位上不适用**，声明豁免。真正需要对照的是：通用原则（第 5、7、8、9、10、12、18 条）+ 数据治理四条铁律 + 设计红线。

## 二、通用原则逐条对照

| 条款 | 结论 | 依据 |
| :--- | :--- | :--- |
| 第五条 减法优先 | ✅ 符合 | 功能聚焦「搜索/导出/导入」三件事，无功能堆砌；搜索导出的多选项属导出场景的必要复杂度 |
| 第七条 用户主权 | ✅ 符合 | 导入导出均用户主动触发、导入有覆盖确认弹窗；提供「删除单个对话 / 删除所有对话 / 清空历史」，删除时明确提示不可恢复；数据本地存储不上传 |
| 第八条 善行无辙迹 | ✅ 符合 | 无推送、无通知、无广告、无日报，无「欢迎使用」问候语 |
| 第九条 坦诚透明 | ⚠️ 基本符合 | 本身不生成 AI 内容；README 已标注「derived from official chat-demo」，二开身份透明 |
| **第十条 外挂增强** | ❌ **偏离** | 本项目为 fork 二开，非外挂模式（见第四节） |
| 第十二条 性分自觉 | ✅ 符合 | 清楚自己是「工具」，不伪装 AI、不替代用户做决定、不冒充权威 |
| 第十八条 身体第一性 | ✅ 符合 | 无无限下拉、无排行榜、无成瘾机制、无推送提醒 |

## 三、数据治理四条铁律（v2.1.0 重点）

| 铁律 | 结论 | 依据 |
| :--- | :--- | :--- |
| 一 源头减量 | ✅ 符合 | 只采集用户主动给出的：API Key（主动填）、对话（主动产生/导入）；无埋点、无行为采集 |
| 二 分级治理 | ✅ 符合 | 会话（IndexedDB）、草稿、API Key（localStorage）均可删除，各有生命周期 |
| 三 脱敏流转 | ⚠️ 基本符合 | 对话数据默认不出设备；唯一出设备路径是用户主动「导出」与「调用 DeepSeek API」。可优化：导出时应提示「含个人对话，请妥善保管」（当前无） |
| 四 降解消亡 | ✅ 符合 | 「删除所有对话」是 IndexedDB 真删除（非软删除归档），删除后不可恢复 |

## 四、核心偏离与整改路径

**唯一实质偏离：第十条「外挂增强原则」。**

宪法要求「不修改宿主核心代码，通过外部模块/钩子/扩展点集成，随时回退」。本项目采用 **fork 模式**——直接在官方 chat-demo 源码上改动（改 schema.ts / importArchive.ts，新增 export/ 组件、globalSearch.ts、legacy.ts 等）。

**缓解措施（已落地）**：双轨分支——`main` 永久镜像上游、`custom` 承载二开，实现「随时回退」的精神，只是手段不同。

**整改路径**：
- **A 备案偏离（推荐）**：在 README/文档明确声明「本项目为 fork 二开，非外挂增强」，作为开发者工具的已知偏离备案。
- **B 严格对齐**：重构成「外挂/插件」形态（独立目录 + 钩子注入），成本高、与现有 fork 架构冲突大。
- **C 迁移至 DSH 插件**：见《DSH插件化可行性评估.md》，长期可彻底消除偏离。

**两个可优化点**：
1. 导出时加隐私提示（数据脱敏流转）。
2. API Key 明文存 localStorage 的透明说明（客户端常规做法，需在文档标注）。

## 五、结论

deepseek-chat-manager 在用户主权、数据治理四条铁律、减法优先、善行无辙迹、身体第一性等核心原则上**完全符合**宪法；唯一实质偏离是「外挂增强 vs fork 二开」，已通过双轨分支部分缓解。作为非陪伴类的开发者工具，建议按「路径 A」备案偏离，并按可优化点做轻量补齐。
