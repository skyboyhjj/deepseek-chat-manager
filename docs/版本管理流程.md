# 版本管理流程

> 适用于 `deepseek-chat-manager` 二开项目的版本发布、打标与下载包管理。
> 本文档基于第一阶段开发完成后的版本管理规划沉淀，与《上游 Bug 修复与提 PR 标准流程》并列，共同构成项目的交付规范。

---

## 0. 版本线与语义化版本（SemVer）

版本号格式 `MAJOR.MINOR.PATCH`：

| 变更类型 | 升位 | 示例 |
| :--- | :--- | :--- |
| 破坏性变更（数据格式不兼容、大重构） | MAJOR | `1.0.0 → 2.0.0` |
| 向后兼容的新功能（如 DSH 插件化） | MINOR | `1.0.0 → 1.1.0` |
| bug 修复 | PATCH | `1.0.0 → 1.0.1` |

---

## 1. 版本号起点

- 二开独立版本线，起点 **`1.0.0`**（首个正式版）。
- `package.json` 的 `version` 由继承上游的 `0.1.2` 提升为 `1.0.0`。
- 之后每版只升对应位，不复用上游版本号。

---

## 2. 发布前准备

每次发布前，完成两处改动：

1. 更新 [package.json](file:///E:/00-DS-chat-demo/package.json) 的 `version`。
2. 更新 `CHANGELOG.md`（按 Keep a Changelog 风格，分「新增 / 修复 / 变更」三组记录）。

`CHANGELOG.md` 条目模板：

```markdown
## [1.0.0] - 2026-11-21

### 新增
- 全局搜索导出（MD / CSV / JSONL）
- 会话级选择性导出（勾选会话打包 ZIP）
- 旧版导出 ZIP 导入兼容

### 修复
- 会话菜单移向删除项时漂移到屏幕左上角
```

---

## 3. 三关验证

提交打标前，三关全绿才放行：

```bash
pnpm type    # tsc 0 错误
pnpm lint    # oxlint 0 警告 0 错误
pnpm build   # --mode production 编译成功，产物落 dist/
```

- 涉及交互的功能，另补浏览器端到端验证（静态检查覆盖不到状态残留类问题）。

---

## 4. 提交与打标

```bash
# 1. 提交版本号 + CHANGELOG
git add package.json CHANGELOG.md
git commit -m "chore(release): v1.0.0"

# 2. 打 annotated tag（打在 custom 分支）
git tag -a v1.0.0 -m "v1.0.0"

# 3. 推送分支与 tag
git push origin custom
git push origin v1.0.0
```

---

## 5. 打包产物

```powershell
# PowerShell（Windows）：压缩 dist 目录
Compress-Archive -Path dist\* -DestinationPath deepseek-chat-manager-v1.0.0.zip
```

```bash
# Linux/macOS：等价命令
cd dist && zip -r ../deepseek-chat-manager-v1.0.0.zip .
```

产物命名固定为 `deepseek-chat-manager-vX.Y.Z.zip`。

---

## 6. 创建 GitHub Release

1. GitHub 仓库 → Releases → Draft a new release。
2. `Choose a tag` 选刚推送的 `v1.0.0`。
3. 上传上一步打包的 `deepseek-chat-manager-v1.0.0.zip`。
4. Release notes 直接贴 `CHANGELOG.md` 对应版本段落。

> 注意：gh CLI 对上游无权限时用网页操作；本项目 release 建在自己的 `skyboyhjj/deepseek-chat-manager` 仓库（`custom` 分支）。

## 7. 下载包管理

### 7.1 产物命名无需 OS/架构后缀

`dist/` 产物是**纯静态 Web 资源**（`.js` / `.css` / `.html` / 字体 `.woff/.ttf/.woff2`），**不含任何二进制可执行文件、`.wasm` 或原生模块**。

- 运行时由浏览器解释执行 JS，**与操作系统（Windows/Linux/macOS）和芯片架构（Arm/x86）完全无关**。
- zip 是平台无关格式，Windows 与 Linux 生成的包可互相解压。
- 「构建」需要 Node 环境，但那是构建时依赖，产物本身跨平台。

因此 `deepseek-chat-manager-v1.0.0.zip` 一个包即可覆盖所有平台，**无需** `windows/linux` 或 `arm64/x86_64` 后缀。

> 例外：若未来推出桌面离线版（Electron/Tauri）或原生 CLI，才需按 `{os}-{arch}` 追加平台标识。

### 7.2 产物不入库

- `dist/` 构建产物**不入库**（`.gitignore` 已忽略），仅作为 release asset 分发。
- 历史版本经 GitHub Releases 归档，用户可下载任意历史版本。

## 9. 全流程 Checklist

- [ ] 更新 `package.json` `version`
- [ ] 更新 `CHANGELOG.md`
- [ ] `pnpm type` / `pnpm lint` / `pnpm build` 三关全绿
- [ ] （交互功能）浏览器端到端验证
- [ ] `git commit -m "chore(release): vX.Y.Z"`
- [ ] `git tag -a vX.Y.Z -m "vX.Y.Z"`
- [ ] `git push origin custom && git push origin vX.Y.Z`
- [ ] 打包 `deepseek-chat-manager-vX.Y.Z.zip`
- [ ] GitHub 建 release 并上传产物、贴 changelog
