# 版本管理流程

> 适用于 `deepseek-chat-manager` 二开项目的版本发布、打标与下载包管理。
> 本文档基于双轨分支架构（`main` 镜像上游、`custom` 承载二开）细化，与《上游 Bug 修复与提 PR 标准流程》并列。

---

## 0. 版本号「双轨模型」

| 分支 | `version` 字段含义 | 状态 | tag 归属 |
| :--- | :--- | :--- | :--- |
| `main` | 上游镜像版本（永远等于 upstream） | `0.1.3` | 不打二开 tag |
| `custom` | 二开产品版本 | 日常跟基线 `0.1.3`，发布切 `1.0.0` | `v1.0.0` 起只打 custom |

**核心：`version` 字段在两轨各有含义、解耦。**

- `main`：`version` 永远跟随上游，由同步天然更新，无需人工干预。
- `custom`：日常开发时 `version` 跟随「最近合入的上游版本」作为基线标记；**发布动作时切换到二开独立版本号**。

---

## 1. tag 命名空间隔离（避免冲突）

- 上游 tag：`v0.1.x`（major = 0）
- 二开 tag：`v1.x.x` 起（major = 1）

因 major 不同，**天然隔离、永不冲突**。`main` 上的 tag 由上游同步带来（`v0.1.2`、`v0.1.3`），无需人工维护。

---

## 2. 语义化版本（SemVer）

| 变更类型 | 升位 | 示例 |
| :--- | :--- | :--- |
| 破坏性变更（数据格式不兼容、大重构） | MAJOR | `1.0.0 → 2.0.0` |
| 向后兼容的新功能（如 DSH 插件化） | MINOR | `1.0.0 → 1.1.0` |
| bug 修复 | PATCH | `1.0.0 → 1.0.1` |

---

## 3. 发布前准备

每次发布，在 `custom` 上完成两处改动：

1. [package.json](file:///E:/00-DS-chat-demo/package.json) `version` 切到二开版本号（如 `1.0.0`）。
2. 更新 `CHANGELOG.md`（Keep a Changelog 风格，分「新增 / 修复 / 变更」）。

```markdown
## [1.0.0] - 2026-11-21

### 新增
- 全局搜索导出（MD / CSV / JSONL）
- 会话级选择性导出（勾选会话打包 ZIP）
- 旧版导出 ZIP 导入兼容

### 修复
- 会话菜单移向删除项时漂移到屏幕左上角
```

---

## 4. 三关验证

```bash
pnpm type    # tsc 0 错误
pnpm lint    # oxlint 0 警告 0 错误
pnpm build   # --mode production，产物落 dist/
```

涉及交互的功能另补浏览器端到端验证。

---

## 5. 提交与打标

```bash
git add package.json CHANGELOG.md
git commit -m "chore(release): v1.0.0"

# 只打 annotated tag，永远在 custom
git tag -a v1.0.0 -m "v1.0.0"

git push origin custom
git push origin v1.0.0
```

> 注意：**不要**在 `main` 打二开 tag。

---

## 6. 打包产物

```powershell
# Windows
Compress-Archive -Path dist\* -DestinationPath deepseek-chat-manager-v1.0.0.zip
```

```bash
# Linux/macOS
cd dist && zip -r ../deepseek-chat-manager-v1.0.0.zip .
```

产物命名固定 `deepseek-chat-manager-vX.Y.Z.zip`（用二开版本号）。

---

## 7. 创建 GitHub Release

1. Releases → Draft a new release → 选 `v1.0.0`。
2. 上传 `deepseek-chat-manager-v1.0.0.zip`。
3. Release notes 贴 `CHANGELOG.md` 对应段落。

---

## 8. 下载包管理

- 产物是**纯静态 Web 资源**（`.js/.css/.html/字体`），无二进制/`.wasm`/原生模块，由浏览器解释执行，**跨 OS 与芯片架构**，故命名**无需 `windows/linux` 或 `arm64/x86_64` 后缀**。
- `dist/` 不入库（`.gitignore` 已忽略），仅作 release asset 分发。
- 历史版本经 GitHub Releases 归档。

> 例外：未来若推桌面离线版（Electron/Tauri）或原生 CLI，才需按 `{os}-{arch}` 追加平台标识。

---

## 9. 同步上游时的 version 处理

- `main`：直接 `fast-forward` 到 `upstream/main`，`version` 自动等于上游最新。
- `custom`：`merge upstream/main` 时，`package.json` 的 `version` 若冲突，**保持「最近合入的上游版本」为基线**（如 `0.1.3`），`name`/`description` 保留二开；直到下一次发布动作，才把 `version` 切到独立版本号。

---

## 10. 后续自动化（可选，暂不启用）

稳定后可用 GitHub Actions 在 `git push origin vX.Y.Z` 时自动 `build` + 建 release + 上传产物。

---

- [ ] `package.json` `version` 切到二开版本号
- [ ] 更新 `CHANGELOG.md`
- [ ] `pnpm type` / `pnpm lint` / `pnpm build` 三关全绿
- [ ] （交互功能）浏览器端到端验证
- [ ] `git commit -m "chore(release): vX.Y.Z"`
- [ ] `git tag -a vX.Y.Z -m "vX.Y.Z"`（只在 custom）
- [ ] `git push origin custom && git push origin vX.Y.Z`
- [ ] 打包 `deepseek-chat-manager-vX.Y.Z.zip`
- [ ] GitHub 建 release、上传产物、贴 changelog
